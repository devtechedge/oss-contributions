# OSS Contributions Ledger v1.0.0

**Release date:** 14 Sep 2026

## Overview

Version 1.0.0 establishes the first versioned baseline for the OSS Contributions Ledger. This repository is the public, auditable record of upstream open-source contribution activity across Web3 and non-Web3 projects. Its purpose is to distinguish verified upstream outcomes from plans, experiments, personal projects, and work that has not yet been accepted. The ledger is maintained against authoritative GitHub repository state so that merged, open, closed, claimed, and planned work are not conflated.

## Current contribution record

At this release, the ledger records **10 merged upstream pull requests** spanning Recharts, pnpm, node-postgres, Biome, SQLMesh, Better Auth, Anza Kit, and thirdweb. The work covers TypeScript, JavaScript, Rust, and Python ecosystems, with contributions involving developer tooling, frameworks, databases, concurrency, portability, security, accessibility, SDKs, testing, and blockchain infrastructure.

The merged record includes Recharts #7805; node-postgres #3772; pnpm #14753, #14756, and #14754; SQLMesh #6040; Better Auth #11208; Biome #11667; Anza Kit #2032; and thirdweb #8938. These entries represent upstream contributions that reached a merged state, rather than proposed changes alone.

## Notable merged work

Recharts #7805 removed `tabIndex={-1}` from z-index portal SVG groups so empty layers are not pointer-focusable, preventing unwanted WebKit geometry-traced focus rings, with regression coverage confirming that rendered layers do not carry a `tabindex` attribute. Node-postgres #3772 corrected `Connection.sync()` lifecycle handling so later connection errors are not swallowed. pnpm contributions addressed lockfile behavior, version-range preservation, and non-recursive script failure handling. SQLMesh #6040 removed a race caused by test execution on shared timing state. Better Auth #11208 added regression coverage for a phone-number verification OpenAPI request-body contract. Biome #11667 introduced the `useBetterDomTraversing` nursery rule with fixtures and release integration. Anza Kit #2032 restored accurate `number` predicates in codec documentation examples, while thirdweb #8938 ensured genuine `useTokenQuery` request failures are rethrown rather than mislabeled as unsupported tokens.

## Ledger architecture

The repository is organized around three complementary records. `README.md` provides the public contribution index and concise descriptions. `docs/triage/triage.json` is the operational source of truth for issue and pull-request tracking, state, and provenance. `docs/Devayan_Mandal-resume.txt` keeps the merged contribution record synchronized with the portfolio-facing resume artifact.

## Provenance and state discipline

The ledger deliberately separates upstream facts from internal planning. A contribution is counted as merged only when GitHub reports the upstream pull request as merged. Open, closed-without-merge, claimed, and planned work remain distinct states. Personal repository work is not presented as upstream contribution history, and speculative future outcomes are excluded from the merged count.

## What v1.0.0 establishes

This inaugural release provides a stable public baseline against which future contribution history can be compared. Subsequent releases should document meaningful additions, verified state changes, or material improvements to the ledger itself rather than arbitrary snapshots. The goal is a durable record that is concise enough for portfolio use while retaining sufficient provenance for independent verification.
